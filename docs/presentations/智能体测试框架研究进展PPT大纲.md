## 3. 研究背景

- 软件系统功能复杂，传统人工编写测试用例成本高、效率低。
- 大语言模型具备需求理解、测试步骤生成和代码生成能力，可用于自动化测试生成。
- 仅依赖 LLM 直接生成测试用例存在不稳定、遗漏需求、缺少反馈优化等问题。
- 因此，本研究构建智能体测试框架，通过生成、审计、修复和动态决策提升测试生成质量。

## 4. 当前研究问题

当前阶段主要关注以下问题：

- 如何让 LLM 生成的测试用例更贴合真实需求。
- 如何减少测试用例中的遗漏、错误和幻觉。
- 如何构建生成、审计、修复的闭环流程。
- 如何避免固定轮次迭代带来的无效调用成本。
- 如何通过实验验证智能体框架的有效性。

## 5. 总体研究思路

```text
需求文档 / 页面信息 / 接口信息
        ↓
RAG 检索增强
        ↓
Creator Agent 生成测试用例
        ↓
Auditor Agent 审计测试用例
        ↓
Repair Agent 修复问题用例
        ↓
RL 决策模块控制迭代流程
        ↓
输出并执行自动化测试用例
```

## 6. 框架整体架构

智能体测试框架主要包含五层：

- **输入层**：需求文档、接口信息、页面结构、历史测试结果。
- **知识增强层**：语义切片、向量检索、Top-K 上下文召回。
- **多智能体协作层**：Creator、Auditor、Repair、Coordinator。
- **决策优化层**：基于 PPO / DQN 的动态迭代决策。
- **测试执行层**：执行生成的自动化测试用例并反馈结果。

## 8. 核心进展一：RAG 检索增强

### 8.1 增强动机

LLM 直接生成测试用例时，容易出现上下文不足、业务规则遗漏和步骤泛化的问题。

### 8.2 实现思路

- 对需求文档、页面说明、接口描述进行语义切片。
- 将切片后的内容向量化存储。
- 在生成测试用例前检索相关上下文。
- 将检索结果作为 Creator Agent 的输入。

### 8.3 预期效果

- 提高测试用例与需求之间的匹配度。
- 降低测试步骤胡编和遗漏的概率。
- 提升需求覆盖率。

## 9. 核心进展二：多智能体协作机制

### 9.1 Agent 角色设计

| Agent | 职责 |
|---|---|
| Creator Agent | 根据需求和检索上下文生成测试用例 |
| Auditor Agent | 审计测试用例质量并输出问题 |
| Repair Agent | 根据审计反馈修复测试用例 |
| Coordinator | 控制多智能体协作流程 |

### 9.2 协作流程

```text
Creator 生成测试用例
        ↓
Auditor 审计问题
        ↓
Repair 修复用例
        ↓
Coordinator 判断是否进入下一轮
```

### 9.3 当前价值

- 将单次 LLM 生成变成多轮反馈优化。
- 将测试生成、质量审查和问题修复拆分为不同角色。
- 提高框架的可扩展性和可解释性。

## 10. 核心进展三：强化学习动态决策

### 10.1 原有问题

当前 Creator-Auditor 流程如果采用固定轮次迭代，会出现两个问题：

- 质量已经足够时仍继续迭代，造成调用成本浪费。
- 质量不足时固定停止，导致测试用例质量不稳定。

### 10.2 增强思路

引入强化学习决策模块，让系统根据当前状态动态判断：

- 是否继续迭代。
- 是否接受当前结果。
- 是否切换生成策略。

### 10.3 状态空间 State

- 当前迭代轮次。
- Auditor 发现的问题数量。
- 严重问题数量。
- 当前需求覆盖率。
- 测试执行通过率。
- 上一轮修复成功数量。
- LLM 调用成本。

### 10.4 动作空间 Action

- 继续迭代。
- 接受当前测试用例。
- 切换 Prompt 策略重新生成。

### 10.5 奖励函数 Reward

- 覆盖率提升给予正奖励。
- 测试通过率提升给予正奖励。
- 审计通过给予正奖励。
- 错误数量增加给予负奖励。
- 无效迭代和调用成本增加给予负奖励。

### 10.6 计划使用算法

- PPO：作为主要强化学习算法。
- DQN：作为离散动作场景下的对比算法。

## 12. 实验设计

### 12.1 实验场景

围绕电商系统典型业务流程开展实验：

- 用户登录。
- 商品搜索。
- 商品详情查看。
- 加入购物车。
- 修改购物车。
- 创建订单。
- 地址管理。
- 后台商品管理。
- 后台订单管理。

### 12.2 对比方法

| 方法 | 说明 |
|---|---|
| LLM Only | 仅使用 LLM 直接生成测试用例 |
| LLM + RAG | 加入检索增强 |
| Creator-Auditor | 加入多智能体审计 |
| Creator-Auditor + Repair | 加入修复智能体 |
| Creator-Auditor + RL | 加入强化学习动态决策 |

### 12.3 评价指标

- 测试用例通过率。
- 需求覆盖率。
- 缺陷检测率。
- 审计通过率。
- 平均迭代轮次。
- 平均生成时间。
- LLM 调用成本。
- 修复成功率。

## 13. 消融实验设计

| 实验 | 对比内容 | 目的 |
|---|---|---|
| RAG 消融 | 有 RAG vs 无 RAG | 验证检索增强效果 |
| Auditor 消融 | 有 Auditor vs 无 Auditor | 验证审计智能体效果 |
| Repair 消融 | 有 Repair vs 无 Repair | 验证修复智能体效果 |
| RL 消融 | 固定轮次 vs RL 动态决策 | 验证强化学习决策效果 |
| 算法对比 | PPO vs DQN | 比较不同决策算法效果 |

## 2. 研究背景

- 软件测试用例生成是保障软件质量的重要环节。
- 大语言模型具备较强的自然语言理解与代码生成能力，可用于辅助测试用例生成。
- 仅依赖 Prompt 编排的方法存在生成结果不稳定、流程不可控、缺乏学习能力等问题。
- 多智能体协作与强化学习可以为测试生成过程提供更强的动态优化能力。

## 3. 现有问题

当前方案主要存在以下问题：

- **流程固定**：Creator-Auditor 采用固定轮次迭代，无法根据测试质量动态调整。
- **算法贡献不足**：系统主要依赖 Prompt 编排，缺少明确的算法优化模块。
- **框架支撑较弱**：自建 Agent 封装较轻量，工程可信度和可扩展性有限。
- **实验维度不足**：缺少与基线方法、不同策略和不同模型之间的系统对比。

## 4. 研究目标

- 构建面向自动化测试生成的多智能体协作框架。
- 引入强化学习算法优化生成、审计与迭代决策过程。
- 提高测试用例的需求覆盖率、通过率和缺陷发现能力。
- 降低固定迭代带来的无效调用成本。

## 5. 相关研究

### 5.1 LLM 测试用例生成

- 基于大语言模型生成单元测试、接口测试或自动化测试脚本。
- 优点是生成能力强，缺点是结果存在幻觉和不稳定性。

### 5.2 多智能体测试生成

- 通过 Creator、Auditor、Repair 等不同角色协作完成测试生成。
- 相比单 Agent，更适合处理生成、审查、修复等复杂流程。

### 5.3 强化学习优化测试生成

- 强化学习可用于动态决策、策略选择和测试用例排序。
- PPO、DQN、MARL 等算法可用于测试生成过程中的策略优化。

## 6. 总体技术路线

```text
需求文档 / 接口文档
        ↓
语义切片与 RAG 检索
        ↓
Creator Agent 生成测试用例
        ↓
Auditor Agent 审计测试用例
        ↓
RL 决策模块判断
继续迭代 / 接受输出 / 切换策略
        ↓
输出最终测试用例
```

## 7. 系统核心模块

### 7.1 RAG 检索模块

- 对需求文档、接口文档等资料进行语义切片。
- 使用向量检索召回与当前任务最相关的上下文。
- 通过 Top-K 检索结果增强测试用例生成质量。

### 7.2 Creator Agent

- 根据需求描述、接口信息和检索上下文生成测试用例。
- 输出测试步骤、输入数据、预期结果和自动化脚本。

### 7.3 Auditor Agent

- 审查测试用例是否覆盖需求点。
- 检查测试步骤、断言、边界条件和异常场景是否完整。
- 输出问题列表和修复建议。

### 7.4 RL 决策模块

- 根据当前审计结果和历史迭代信息进行动态决策。
- 判断是否继续迭代、接受当前结果或切换生成策略。
- 替代原有固定 3 轮迭代机制。

### 7.5 Healing / Repair 模块

- 对失败或不完整的测试用例进行修复。
- 可结合规则修复、LLM 重写和策略选择机制提升修复效率。

## 8. 核心增强一：多智能体协作机制

| 对比项 | 原方案 | 增强后 |
|---|---|---|
| Agent 实现 | 自建 BaseAgent | AutoGen AssistantAgent |
| 协作方式 | 手写流程控制 | GroupChat / Coordinator |
| 审计机制 | 固定 Auditor 审计 | 多 Agent 协作审计 |
| 可扩展性 | 较弱 | 便于扩展新角色 |
| 工程可信度 | 一般 | 基于成熟开源框架 |

增强后，系统不再只是简单调用 LLM，而是通过标准化多智能体框架组织生成、审计和修复流程。

## 9. 核心增强二：强化学习决策算法

本文重点引入强化学习算法优化 Creator-Auditor 的迭代决策。

### 9.1 状态空间 State

- 当前迭代轮次。
- Auditor 发现的问题数量。
- 严重问题数量。
- 当前需求覆盖率。
- 上一轮修复成功数量。
- LLM 调用成本。

### 9.2 动作空间 Action

- 继续迭代。
- 接受当前结果。
- 切换 Prompt 策略后重新生成。

### 9.3 奖励函数 Reward

- 覆盖率提升给予正奖励。
- 审计通过给予正奖励。
- 发现幻觉、错误或遗漏给予负奖励。
- 增加迭代轮次和模型调用成本给予负奖励。
- 修复失败给予负奖励。

## 10. PPO / DQN 算法设计

### 10.1 PPO 算法

- 使用 Stable-Baselines3 实现 PPO 智能体。
- PPO 用于学习在不同审计状态下的最优迭代策略。
- 适合在质量收益和调用成本之间进行稳定权衡。

### 10.2 DQN 算法

- DQN 适合处理离散动作空间。
- 本文动作包括继续迭代、接受输出和切换策略，天然属于离散决策问题。
- 可作为 PPO 的对比算法或候选实现。

### 10.3 推荐主线

论文汇报中建议将 PPO 作为主要算法，DQN 作为补充或对比算法。否则算法太多，主线容易发散。

## 11. 测试自愈策略优化

测试用例执行失败后，系统可以根据失败类型选择不同修复策略：

- 替换元素定位器。
- 增加等待时间。
- 重新生成断言。
- 调用 LLM 重写测试代码。
- 回退到历史可用版本。

可扩展引入 Multi-Armed Bandit 算法：

- UCB。
- Thompson Sampling。

该部分建议作为扩展模块或未来工作，不建议抢占 PPO 决策算法的主线位置。

## 16. 创新点总结

### 16.1 基于强化学习的动态迭代决策方法

将固定轮次的 Creator-Auditor 流程改造为可学习的动态决策流程，使系统能够根据审计反馈自动判断是否继续优化。

### 16.2 多智能体协作式测试生成框架

构建 Creator、Auditor、Repair 等多角色协作机制，实现测试生成、审计和修复的闭环流程。

### 16.3 面向测试生成任务的奖励函数设计

综合考虑需求覆盖率、审计结果、错误数量、修复效果和模型调用成本，设计适用于测试生成场景的奖励函数。

## 17. 不足与展望

### 17.1 不足

- 强化学习训练需要一定数量的实验样本。
- 不同项目之间的泛化能力仍需进一步验证。
- LLM 输出仍存在不确定性。
- 对复杂业务系统的覆盖能力仍有提升空间。

### 17.2 展望

- 扩大实验项目和测试数据规模。
- 引入 MARL 实现多个 Agent 的联合策略优化。
- 引入测试用例优先级排序算法。
- 进一步优化测试自愈策略选择。

## 18. 总结

本文通过引入多智能体协作机制和强化学习决策算法，将传统基于 Prompt 的测试生成流程升级为可审计、可优化、可动态决策的智能测试生成系统。

核心增强包括：

- 使用 AutoGen 提升多智能体协作能力。
- 使用 PPO / DQN 优化 Creator-Auditor 迭代决策。
- 使用 RAG 提升测试生成上下文质量。
- 通过消融实验和基线对比验证系统有效性。

## 19. 汇报主线建议

汇报时建议聚焦一条主线：

```text
固定迭代不可控
        ↓
引入 Creator-Auditor 审计闭环
        ↓
使用 PPO 强化学习动态决策
        ↓
减少无效迭代，提高覆盖率和通过率
```

不要把 PPO、DQN、MARL、Bandit、BERT 全部包装成核心创新。最稳的做法是：

- PPO 是主算法。
- DQN 是对比算法。
- AutoGen 是工程框架。
- Bandit 和 MARL 放扩展或展望。

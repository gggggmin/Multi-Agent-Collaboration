# 组会汇报 PPT 调整建议

## 一、当前 PPT 不清楚的核心原因

现在这版 PPT 最大的问题不是内容不够，而是内容太像“最终论文方案介绍”，不像“组会进展汇报”。

主要问题有四个：

1. **已完成、正在做、计划做没有区分清楚**
   - RAG、AutoGen、Repair、PPO、DQN、实验设计都被放在一起讲。
   - 导师听起来会分不清哪些已经实现，哪些只是设计方案。

2. **每页文字偏概念化**
   - 比如“质量螺旋式上升”“自我进化循环”“工业化应用”这类表达听起来很宏大，但组会更需要具体进展。
   - 应该换成：做了哪个模块、输入是什么、输出是什么、目前跑通到哪一步。

3. **研究问题太多，主线被冲散**
   - 当前 PPT 同时讲需求对齐、质量保障、闭环优化、成本效益、有效性验证。
   - 这些都对，但开头一下抛 5 个问题，导师容易抓不住你这阶段的核心。

4. **“完成的工作”页不够硬**
   - 第 5 页写了初始框架、Creator、Auditor、实验环境，但缺少具体产物。
   - 应该明确写：完成了哪些代码模块、生成了什么测试用例、在哪些业务场景上跑过、当前输出样例是什么。

## 二、组会汇报应该换成什么主线

建议把汇报主线改成：

```text
我想解决什么问题
        ↓
我设计了什么框架
        ↓
我目前已经完成了哪些模块
        ↓
当前效果和问题是什么
        ↓
下一步准备怎么增强
```

这才是组会汇报的逻辑。别一上来就把最终论文形态全摊开，容易显得“画饼很大，进展不实”。

## 三、建议修改后的 PPT 结构

### 第 1 页：题目页

标题建议：

> 智能体自动化测试生成框架研究进展汇报

不要把标题写得太大，比如“基于多智能体协作与强化学习的智能体测试框架研究”。如果 PPO 还没真正落地，标题里太早强调强化学习，导师一问实现细节容易被动。

### 第 2 页：本次汇报内容

建议放 4 点：

- 研究目标与问题
- 当前框架设计
- 已完成工作
- 后续增强计划

这页是给导师建立预期：今天不是最终答辩，是阶段性进展。

### 第 3 页：研究目标

建议这样讲：

> 本研究希望构建一个智能体自动化测试生成框架，让大模型不只是一次性生成测试用例，而是能够结合需求上下文，经过生成、审计、修复和迭代决策，输出更可靠的自动化测试用例。

页面要点：

- 输入：需求文档、页面信息、接口信息
- 输出：结构化测试用例 / 自动化测试脚本
- 目标：提高覆盖率、通过率，减少人工编写成本

### 第 4 页：当前问题

建议保留 3 个核心问题，别写 5 个。

- **上下文不足**：LLM 容易遗漏需求和业务规则。
- **质量不可控**：一次性生成的测试用例可能有错误、遗漏或断言不合理。
- **迭代策略固定**：固定轮次生成会造成过度迭代或迭代不足。

这三个问题刚好对应你的三个增强模块：

- RAG
- Creator-Auditor-Repair
- PPO / DQN 动态决策

### 第 5 页：总体框架设计

这一页保留流程图，但要更清楚地区分模块：

```text
需求 / 页面 / 接口信息
        ↓
RAG 检索增强
        ↓
Creator 生成测试用例
        ↓
Auditor 审计问题
        ↓
Repair 修复用例
        ↓
Coordinator / RL 决策是否继续迭代
        ↓
输出并执行测试用例
```

讲的时候重点说：

- 当前已经跑通 Creator-Auditor 基础链路。
- RAG、Repair、RL 是下一阶段重点增强。

### 第 6 页：已完成工作一：基础生成流程

这一页要讲具体产物。

建议内容：

- 已完成需求输入到测试用例生成的基础流程。
- 已设计测试用例结构，包括测试目标、前置条件、测试步骤、测试数据、预期结果。
- 已针对电商典型场景进行测试用例生成验证。

建议加一个小样例：

| 输入需求 | 生成结果 |
|---|---|
| 用户登录功能 | 正常登录、密码错误、空用户名、账号不存在等测试用例 |

### 第 7 页：已完成工作二：Creator-Auditor 初始闭环

建议内容：

- Creator Agent 负责生成初始测试用例。
- Auditor Agent 从覆盖率、步骤完整性、断言合理性、异常场景四个维度审查。
- 审计结果会反馈给下一轮生成或修复。

建议讲清楚：

> 目前已经形成了生成和审计的基础闭环，但 Repair 自动修复和 RL 决策还在进一步完善。

这句话很关键，边界说清楚，导师反而觉得你靠谱。

### 第 8 页：实验场景与数据准备

不要强调“开源平台”本身，讲实验验证场景即可。

建议内容：

- 实验场景选择电商业务流程。
- 覆盖登录、搜索、商品详情、购物车、订单等功能。
- 后续通过通过率、覆盖率、生成耗时、调用成本等指标评估。

可以补一句：

> 电商系统只是验证载体，研究重点是测试生成框架本身。

### 第 9 页：下一步增强一：RAG 检索增强

建议讲成“为什么要做、准备怎么做、验证什么”。

- 为什么：解决 LLM 上下文不足。
- 怎么做：语义切片、向量化、Top-K 检索、上下文注入。
- 验证什么：需求覆盖率是否提升，幻觉是否减少。

别写太多“知识外挂”这种修辞，导师要听技术路径。

### 第 10 页：下一步增强二：Repair 与多智能体协作

建议内容：

- 增加 Repair Agent，把 Auditor 的问题转化为修复动作。
- 使用 AutoGen 管理多智能体协作流程。
- 形成 Creator-Auditor-Repair-Coordinator 闭环。

要说清楚 AutoGen 的定位：

> AutoGen 是多智能体编排框架，不是本文算法创新点。

### 第 11 页：下一步增强三：RL 动态迭代决策

这一页讲 PPO，但别讲太玄。

建议内容：

- 当前问题：固定 3 轮迭代不合理。
- 解决思路：用 RL 决定继续、停止或切换策略。
- 状态：问题数、覆盖率、通过率、当前轮次、调用成本。
- 动作：继续迭代、接受结果、重新生成。
- 奖励：覆盖率和通过率提升给正奖励，成本和错误给负奖励。

建议表述：

> PPO 是后续核心算法增强，当前重点是先构建可训练的决策环境和奖励函数。

这比直接说“已经实现 PPO 智能决策”稳多了。

### 第 12 页：实验设计

建议对比组：

| 方法 | 目的 |
|---|---|
| LLM Only | 基础基线 |
| LLM + RAG | 验证检索增强 |
| Creator-Auditor | 验证审计机制 |
| Creator-Auditor-Repair | 验证修复闭环 |
| Full Framework + RL | 验证动态决策 |

评价指标：

- 测试用例通过率
- 需求覆盖率
- 缺陷检测率
- 平均迭代轮次
- LLM 调用成本
- 修复成功率

### 第 13 页：当前不足

这页要实话实说，但别写得像没干活。

建议写：

- RAG 检索模块还需要接入并验证检索质量。
- Repair Agent 需要进一步实现自动修复策略。
- RL 决策模块需要构建环境和奖励函数。
- 实验数据还需要补充完整。

### 第 14 页：下一步计划

建议按时间线讲：

| 阶段 | 工作 |
|---|---|
| 第 1 阶段 | 完成 RAG 接入和检索质量验证 |
| 第 2 阶段 | 完成 Repair Agent 和 AutoGen 协作流程 |
| 第 3 阶段 | 构建 RL 环境并接入 PPO |
| 第 4 阶段 | 完成对比实验和消融实验 |

### 第 15 页：总结

建议总结成 3 句话：

1. 当前已完成智能体测试框架的基础设计和 Creator-Auditor 初始闭环。
2. 后续将通过 RAG、Repair Agent 和 PPO 决策模块提升生成质量与迭代效率。
3. 下一阶段重点是完成模块落地和实验数据验证。

## 四、你汇报时应该怎么讲

建议开场这样说：

> 老师，我这次主要汇报智能体测试框架的阶段性进展。当前工作重点不是单纯搭一个测试平台，而是构建一个能够自动生成、审计、修复并动态优化测试用例的智能体框架。目前我已经完成了基础生成流程和 Creator-Auditor 初始闭环，接下来会重点推进 RAG 检索增强、Repair Agent 和 PPO 动态决策模块。

这段话能直接把主线钉住。

## 五、哪些内容建议删减

当前 PPT 里建议删或压缩的内容：

- “自我进化”“工业化应用”“质量螺旋式上升”等宏大表述。
- 每页过长的大段解释。
- 过早强调 PPO 已经形成完整闭环。
- 过多工具名堆叠，比如 OpenAI、DeepSeek、FAISS、Sentence-BERT、AutoGen、Stable-Baselines3 全展开讲。
- Q&A 页上的口号式总结。

## 六、最关键的修改原则

组会汇报要把每个模块标清楚状态：

| 模块 | 当前状态 |
|---|---|
| Creator Agent | 已完成基础生成 |
| Auditor Agent | 已完成初始审计 |
| Repair Agent | 待完善 |
| RAG | 设计完成，待接入验证 |
| AutoGen | 计划用于重构协作流程 |
| PPO / DQN | 算法方案已设计，待构建环境并训练 |
| 实验 | 场景和指标已规划，数据待补充 |

这个表建议直接放进 PPT。它比一堆漂亮话有用多了。

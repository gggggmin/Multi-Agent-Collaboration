# 基于多智能体协同的需求驱动自动化测试生成与自愈方法研究

## 概述

本项目是一个**基于多智能体协同（Multi-Agent Collaboration）的需求驱动自动化测试生成框架**，旨在利用大语言模型（LLM）和多智能体博弈机制，从自然语言需求文档自动生成高质量的测试用例及可执行的测试脚本。框架结合了 RAG（检索增强生成）、多智能体博弈、Page Object 代码生成和自愈（Self-Healing）等核心技术。

## 模块详解

### 1. RAG 知识检索模块 (`framework/rag/`)

该模块负责将自然语言需求文档解析为结构化的语义切片，并构建向量索引以供检索。

| 类 | 文件 | 职责 |
|---|---|---|
| `DocumentParser` | `document_parser.py` | 解析 Markdown 需求文档，按 `## 功能` 标题分割为语义块，提取模块名、功能名、类型标签 |
| `Chunk` | `document_parser.py` | 语义切片的数据结构，包含 module、func_name、content、chunk_type、file_source 五个字段 |
| `SemanticChunker` | `semantic_chunker.py` | 包装 DocumentParser 的切片逻辑，提供统计（`chunk_stats`）和固定长度切片（用于消融实验对比） |
| `Retriever` | `retriever.py` | 基于 ChromaDB 的向量检索，提供 `build_index` 建索引、`retrieve` 语义检索和 `retrieve_by_module` 按模块检索 |
| `EmbeddingEngine` | `retriever.py` | 嵌入引擎，优先使用 HuggingFace `sentence-transformers`（all-MiniLM-L6-v2），加载失败自动降级为 TF-IDF |

**关键技术点**：
- 按功能标题语义切片（vs 固定长度切片），保留业务语义完整性
- 支持语义检索（Query Embedding）和按模块过滤（Metadata Filter）
- 嵌入模型加载失败时自动降级，保证系统鲁棒性

### 2. 多智能体博弈模块 (`framework/multi_agent/`)

这是框架的核心模块，实现了 **Creator-Auditor 博弈机制**，通过多轮迭代提升测试用例质量。

| 类 | 文件 | 职责 |
|---|---|---|
| `BaseAgent` | `base_agent.py` | 所有 Agent 的基类，封装 LLM API 调用（支持 DeepSeek / OpenAI / Claude），含异常处理和降级响应 |
| `CaseCreator` | `case_creator.py` | 生成 Agent：根据需求片段生成覆盖正向、逆向、边界值的测试用例集，输出 JSON 格式。LLM 不可用时使用内置 mock 数据降级 |
| `CaseAuditor` | `case_auditor.py` | 审计 Agent：从一致性和完备性两个维度审计用例，检测"幻觉（Hallucination）"— 即用例中包含需求中未提及的功能。LLM 不可用时使用规则检查降级 |
| `Coordinator` | `coordinator.py` | 协调器：驱动 Creator-Auditor 博弈循环（最多 N 轮），每轮 Creator 生成 → Auditor 审计，不通过则携带审计反馈重新生成 |

**博弈流程**：
```
第 1 轮: Creator 生成用例 → Auditor 审计
  ├─ 通过 → 输出用例
  └─ 不通过 → 携带审计反馈进入第 2 轮
第 2 轮: Creator 根据审计反馈重新生成 → Auditor 再次审计
  ├─ 通过 → 输出用例
  └─ 不通过 → ...
...
第 N 轮: 强制结束，输出当前结果
```

**审计维度**：
- **一致性（Consistency）**：检查用例的每个步骤和预期结果是否能在需求中找到依据，标记"幻觉"
- **完备性（Completeness）**：检查是否遗漏关键场景（正向、逆向、边界值是否覆盖全面）

### 3. 测试脚本代码生成模块 (`framework/code_gen/`)

将经过审计通过的测试用例转化为可执行的测试代码。

| 类 | 文件 | 职责 |
|---|---|---|
| `PageAgent` | `page_agent.py` | 分析测试用例，提取页面元素和操作，生成 Page Object 类（继承 BasePage）。内置 login/index/cart 三个页面的元素和操作定义 |
| `TestAgent` | `test_agent.py` | 为每个模块生成 Pytest 测试脚本，包含 pytest.mark 标签（positive/negative/boundary）、测试数据、断言框架 |
| `BasePage` | `templates/pom_base.py` | Page Object 基类，封装 Playwright 常用操作（navigate / get_text / is_visible / wait_for_selector / screenshot） |

**输出示例**（Page Object）：
- `output/pages/page_login.py` — 登录页 Page Object（USERNAME_INPUT, PASSWORD_INPUT, LOGIN_BUTTON, login(), get_error_message()）
- `output/pages/page_index.py` — 首页 Page Object（search_input, cart_buttons, search(), add_to_cart()）
- `output/pages/page_cart.py` — 购物车页 Page Object（checkout_link, delete_buttons, go_to_cart(), checkout()）

**输出示例**（测试脚本）：
- `output/test_login.py` — 登录模块的 Pytest 测试脚本

### 4. 自愈模块 (`framework/self_healing/`)

实现测试执行后的闭环修复，增强测试脚本的鲁棒性。

| 类 | 文件 | 职责 |
|---|---|---|
| `SandboxExecutor` | `executor.py` | 沙箱执行器：在子进程中运行 Pytest 脚本，捕获 stdout/stderr，支持超时控制和 PyLint 静态检查 |
| `ErrorDiagnoser` | `error_diagnoser.py` | 错误诊断器：解析 Traceback，按 6 类错误（locator/assertion/timeout/syntax/attribute/import）分类，并给出修复建议 |
| `HealingAgent` | `healing_agent.py` | 自愈 Agent：基于 BaseAgent 调用 LLM，结合诊断结果和修复历史，迭代修复脚本（最多 3 次尝试） |

**自愈流程**：
```
测试脚本 → SandboxExecutor 运行
  ├─ 成功 → 结束
  └─ 失败 → ErrorDiagnoser 诊断错误类型
              └─ HealingAgent 调用 LLM 修复代码
                   └─ 修复后再次执行验证
```

**错误分类**：
| 类别 | 匹配关键字 | 典型场景 |
|---|---|---|
| `locator` | ElementNotFound, TimeoutError | 元素定位器失效 |
| `assertion` | AssertionError | 断言与实际不符 |
| `timeout` | timeout, TimedOut | 页面加载超时 |
| `syntax` | SyntaxError, NameError | 代码语法错误 |
| `attribute` | AttributeError | 引用了不存在的方法 |
| `import` | ModuleNotFoundError | 缺少依赖或导入路径错误 |

### 5. 实验评价模块 (`experiments/`)

用于验证框架效果的实验体系和评价指标。

| 类/函数 | 文件 | 职责 |
|---|---|---|
| `Evaluator` | `evaluation.py` | 计算三大评价指标：需求覆盖率、幻觉率、自愈成功率；提供消融实验对比功能 |
| `experiment_full()` | `run_experiments.py` | 完整实验：RAG → 多智能体博弈（4个模块）→ 评价 → 保存结果 |
| `experiment_ablation()` | `run_experiments.py` | 消融实验：对比有/无 Auditor 时的覆盖率和幻觉率差异 |

**评价指标**：

| 指标 | 说明 | 计算方式 |
|---|---|---|
| **需求覆盖率** | 生成的用例覆盖了多少需求 | 覆盖需求数 / 总需求数 × 100% |
| **幻觉率** | 生成的用例中无需求依据的比例 | 幻觉用例数 / 总用例数 × 100% |
| **自愈成功率** | 自愈模块修复测试脚本的成功率 | 成功修复次数 / 总尝试次数 × 100% |

**消融实验**：对比有 Auditor（完整博弈） vs 无 Auditor（直接生成）在覆盖率和幻觉率上的差异。

## 配置体系 (`config.py`)

通过环境变量配置，支持灵活切换：

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `LLM_PROVIDER` | `deepseek` | LLM 提供商（openai / deepseek / claude） |
| `LLM_API_KEY` | 环境变量 | API 密钥 |
| `LLM_MODEL` | `deepseek-v4-flash` | 模型名称 |
| `LLM_TEMPERATURE` | 0.3 | 生成温度（较低值提高一致性） |
| `LLM_MAX_TOKENS` | 4096 | 最大 Token 数 |
| `EMBEDDING_MODEL` | `all-MiniLM-L6-v2` | 嵌入模型 |
| `RETRIEVAL_TOP_K` | 3 | 检索返回 Top-K 结果 |
| `MAX_ITERATIONS` | 3 | 最大博弈迭代轮数 |
| `CHROMA_PERSIST_DIR` | `.cache/chroma_db` | ChromaDB 持久化路径 |

## 命令行接口

框架通过 `main.py` 提供 5 个子命令：

```bash
# 1. RAG 知识检索
python main.py rag --query "登录失败的处理方式"

# 2. 多智能体博弈生成用例
python main.py generate --module login           # 带 Auditor（完整博弈）
python main.py generate --module login --no-auditor  # 无 Auditor（直接生成）

# 3. 测试脚本代码生成
python main.py codegen --output output

# 4. 自愈执行
python main.py heal output/test_login.py --fix

# 5. 运行实验
python main.py experiment --type full       # 完整实验
python main.py experiment --type ablation   # 消融实验
python main.py experiment --type all        # 全部
```

## 设计特点与创新

1. **Creator-Auditor 博弈机制**：双角色 LLM Agent 互相校验，减少 LLM 幻觉，提高测试用例质量
2. **多级降级策略**：每个模块都设计了 LLM 不可用时的降级方案，保证基础功能可用
3. **RAG + 多智能体协同**：语义检索确保测试用例严格基于需求，博弈机制确保完备性
4. **自愈闭环**：测试执行 → 错误诊断 → LLM 修复 → 重新验证，形成闭环
5. **模块化架构**：RAG / 多智能体 / 代码生成 / 自愈 / 实验评价各模块独立解耦
6. **多 LLM 提供商支持**：通过 OpenAI SDK 兼容接口，支持 DeepSeek、OpenAI、Claude
7. **完整的实验体系**：内置 Ground Truth 和评价指标，支持消融实验验证各组件贡献度

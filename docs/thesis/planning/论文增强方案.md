## 二、可集成的开源项目

### 2.1 Stable-Baselines3（RL 算法库）⭐ 最推荐

| 项目 | 说明 |
|------|------|
| **GitHub** | https://github.com/DLR-RM/stable-baselines3 |
| **Stars** | 10k+ |
| **定位** | 最成熟的 PyTorch RL 算法库，学术界标准工具 |
| **安装** | `pip install stable-baselines3` |
| **提供算法** | PPO, DQN, A2C, SAC, TD3 等主流 RL 算法 |
| **为什么用它** | 你不用自己实现 RL 算法，直接 import 就行。论文里写"基于 Stable-Baselines3 的 PPO 算法"比"自己写的 RL 代码"有说服力得多 |

**用法示例（3行代码）：**
```python
from stable_baselines3 import PPO

# 定义你的 Gym 环境
env = YourTestGenerationEnv()
# 训练 PPO 智能体
model = PPO("MlpPolicy", env, verbose=1).learn(total_timesteps=10000)
```

## 三、具体增强路线（按优先级排列）

### 路线 A：RL 优化 Creator-Auditor 博弈（最具创新性）

**现状问题**：Creator-Auditor 固定 3 轮迭代，没有任何学习能力。

**改造方案**：

```
┌─────────────────────────────────────────────┐
│  新增：RL 决策模块                             │
│                                              │
│  State（状态）:                                │
│    - 当前轮次 / 最大轮次                        │
│    - 本轮 Auditor 发现的问题数                  │
│    - 严重问题（error）数                        │
│    - 已覆盖的需求数                             │
│    - 上轮修复后新增通过数                        │
│                                              │
│  Action（动作）:                               │
│    0 = 继续迭代（再改一轮）                     │
│    1 = 接受输出（停止）                        │
│    2 = 换策略（切换 Prompt 风格重新生成）         │
│                                              │
│  Reward（奖励）:                               │
│    +覆盖率提升                                 │
│    -每轮迭代成本                               │
│    -幻觉率惩罚                                 │
│    +最终审计通过奖励                            │
│                                              │
│  算法：Stable-Baselines3 PPO / DQN            │
└─────────────────────────────────────────────┘
```

**预期论文贡献**：
- 不再是固定的 3 轮硬编码
- RL 智能体学会在"质量"和"成本"之间权衡
- 可以画收敛曲线图、奖励曲线图（论文标配）
- **公式可写**：状态定义、动作空间、奖励函数、PPO 损失函数

### 路线 B：集成 AutoGen 替换自建 Agent 框架

**现状问题**：你自己的 `BaseAgent` 只是简单封装了 OpenAI SDK，作为硕士论文太单薄。

**改造方案**：
- 用 AutoGen 的 `AssistantAgent` 重写 Creator 和 Auditor
- 用 AutoGen 的 `GroupChat` 和 `RoundRobinManager` 管理博弈流程
- 这样答辩时可以说"基于微软 AutoGen 框架构建多智能体测试系统"

**需要改的代码**：
- `framework/multi_agent/base_agent.py` → 替换为 AutoGen AssistantAgent
- `framework/multi_agent/coordinator.py` → 替换为 AutoGen GroupChat

### 路线 C：消融实验扩展（增加工作量最直接的方式）

你已经有基本的消融实验（有/无 Auditor），可以大幅扩展：

| 实验维度 | 对比组 | 预期结论 |
|---------|--------|---------|
| 切片策略 | 语义切片 vs 固定长度切片 vs 滑动窗口 | 证明你的切片方法最优 |
| 检索策略 | Top-1 vs Top-3 vs Top-5 | 找到最优检索数量 |
| LLM 模型 | DeepSeek vs GPT-4o vs Claude Sonnet | 证明方法不依赖特定模型 |
| RL 决策 | 固定3轮 vs RL 动态决策 | RL 减少不必要的迭代 |
| Auditor 模式 | LLM Auditor vs 规则Auditor vs BERT分类器 | 对比不同审计方法 |
| 基线对比 | 你的方法 vs MetaGPT vs QAagent | 证明你的方法更优（需要集成这俩开源项目） |

### 路线 D：基于 RL 的测试用例优先级排序

**思路**：生成测试用例后，不直接全部输出，而是用 RL 智能体排序。

- 状态：每个用例的特征（类型、涉及模块、复杂度）
- 动作：选择下一个要执行的用例
- 奖励：累积覆盖率、缺陷发现数
- 算法：DQN / PPO

**论文中可以写的**：
- "基于深度强化学习的测试用例优先级排序方法"
- 对比贪心算法、随机排序、基于覆盖的排序

### 路线 E：RL 优化自愈策略选择

**现状**：Healing Agent 每次直接调 LLM 重写代码，成本高。

**改造**：用 **Multi-Armed Bandit**（多臂赌博机）学习选择修复策略

```
策略池：
  策略1: 直接调 LLM 重写（现有方案）
  策略2: 替换元素定位器（规则修复）
  策略3: 增加等待时间（超时修复） 
  策略4: 回退到上一个可用版本

用 UCB / Thompson Sampling 算法选择策略
奖励 = 修复是否成功 + 修复耗时
```

**工具**：可以用 Stable-Baselines3 或自己实现一个简单的 Bandit

## 四、推荐组合方案

考虑到你的时间，我建议按这个组合做：

### Phase 1（基础改造）：集成 AutoGen
- 用 AutoGen 替换自己的 BaseAgent 和 Coordinator
- 工作量：中等（改 2-3 个文件）
- 论文价值：使用成熟开源框架，提升可信度

### Phase 2（核心创新）：添加 RL 博弈决策
- 用 Stable-Baselines3 训练 DQN/PPO 智能体控制迭代终止
- 工作量：中等偏大（需要定义 Gym Environment）
- 论文价值：**这是你论文的算法核心贡献**
- 预期能写一整节：第 3.3.4 节"基于强化学习的博弈终止策略"

### Phase 3（工作量扩充）：扩展消融实验
- 对比 3 种 LLM 模型
- 对比有/无 RL
- 对比语义切片 vs 固定切片
- 工作量：中等（主要是跑实验、收集数据）
- 论文价值：实验丰富度大幅提升，数据表格+折线图

## 小结

你当前的框架作为工程实践还可以，但作为硕士论文确实缺两点：
1. **算法深度** → 引入 RL（Stable-Baselines3）
2. **框架可信度** → 集成成熟开源项目（AutoGen）

两个方向都有对应的高质量论文可以作为理论基础和参考文献，改动量和论文价值是匹配的。

# 开题答辩问题及解决方案

## 一、问题总结

根据老师反馈，当前开题答辩内容主要存在以下两个问题：

### 1. 研究方法与研究内容对应关系不清晰

答辩中虽然列出了4种研究方法，但没有明确说明每一种研究方法分别对应哪些具体研究内容，导致研究方法部分显得较为笼统，缺乏针对性和逻辑支撑。

### 2. 学术研究与工程开发边界不清

当前内容中过多强调系统开发、功能实现和工程落地，容易使论文呈现出“项目开发说明”的倾向，削弱了论文应有的学术研究深度和创新价值。

## 二、解决方案

### 1. 明确4种研究方法的具体对应内容

需要重新梳理研究方法与研究内容之间的关系，做到“一种方法对应一个或多个明确研究任务”。

例如：

- 文献研究法：用于梳理国内外相关研究现状、理论基础和已有成果。
- 对比分析法：用于比较现有方法或系统的优缺点，明确本文研究切入点。
- 实验研究法：用于验证本文提出方法或模型的有效性。
- 案例分析法 / 系统分析法：用于结合具体应用场景分析研究方案的适用性。

修改时应避免只罗列研究方法，而要说明“该方法用于研究什么问题、支撑哪部分论文内容”。

### 2. 弱化工程开发内容

需要删除或压缩系统功能、页面设计、模块实现、部署流程等工程开发细节，避免论文重点偏向软件开发过程。

工程实现可以保留，但应作为研究验证的辅助部分，而不是论文主体。

### 3. 强化学术研究重点

论文重点应转向以下内容：

- 研究问题是什么；
- 现有研究存在哪些不足；
- 本文提出了什么改进方法或研究思路；
- 本文的创新点体现在哪里；
- 如何通过实验、对比或案例分析证明研究方案有效。

### 4. 突出研究创新点

创新点不应只表述为“实现了一个系统”或“完成了某些功能”，而应从学术研究角度进行提炼。

可以从以下方向强化：

- 提出一种改进方法；
- 构建一种分析框架；
- 优化某类模型或算法；
- 设计一套评价指标；
- 验证某方法在特定场景下的适用性。

## 三、修改建议总结

后续修改时，应将论文表述从“工程开发导向”调整为“学术研究导向”。

具体来说：

- 将“我要开发什么系统”改为“本文围绕什么问题展开研究”；
- 将“系统实现了哪些功能”改为“本文提出的方法如何解决现有问题”；
- 将“技术如何落地”改为“研究路径如何支撑论文结论”。

## 四、最终结论

老师提出的问题本质上是：当前开题内容学术研究属性不够突出，工程开发内容偏重。

因此，后续修改应重点解决两个方面：

1. 明确研究方法与研究内容之间的对应关系；
2. 删除或弱化工程实现细节，强化研究问题、研究方法、创新点和验证逻辑。

工程实现只能作为论文研究的支撑，不能成为论文主体。论文真正需要突出的，是研究价值、方法创新和论证过程。
